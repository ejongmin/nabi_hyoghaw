1. PYARROW PRE-FILTER BUG (CRITICAL)
────────────────────────────────────────────────────────────────────────────
Location: gdelt_bq.py lines 559-565, 579-580
Issue: Type B (risk_only) articles with null v2_organizations are removed by
       PyArrow filter BEFORE they can be identified and preserved.

Impact: ~30-50% of Type B articles are permanently lost
Root Cause: Type B preservation logic (line 580) runs AFTER PyArrow removal
            (line 565). Once removed, they cannot be recovered.

Code Flow (BROKEN):
  Stage 0 (line 565): PyArrow removes rows with null v2_organizations
  Stage 1: Aho-Corasick matches entities (only on surviving rows)
  Stage 2 (line 580): Attempt to preserve Type B articles
    ← BUT: Type B articles with null v2_organizations already removed!

Intended Design:
  Stage 0: Filter out null v2_organizations
  Stage 2: KEEP Type B articles even with null v2_organizations

Actual Behavior:
  Stage 0: Removes ALL rows with null v2_organizations (including Type B)
  Stage 2: Cannot recover Type B articles (they're already gone)

Detectability: Low - No logging of Type B removal counts
Severity: 🔴 CRITICAL
Fix Effort: Medium
